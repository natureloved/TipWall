## TipWall — full multi-lens review (product / engineering / protocol / judge / startup)

Deliverable: `TIPWALL-REVIEW.md` at repo root.

### Verified state
- 11,166 LOC TS/TSX, 110 files. `vitest run` = 83 passed (12 files). `eslint src` = clean.
- Live `tipwall.vercel.app`: health OK; ecosystem = 8 walls, 64 verified tips, 19,030 NIM.
- MIT licence ✓, public repo ✓, no env secrets tracked (`.env*` gitignored).
- Competition: Nimiq Mini Apps **Cycle II**, Aug 24 → **Sept 18 2026**. 15 days left at review time.
- Rubric: 45 functionality / 25 Nimiq integration / 15 real usage / 10 design / 5 promotion.
  Est. total 70–81. Real usage is the weakest category AND the only one time can move.

### Critical findings (P0)
1. **C1 no Nimiq address validation** — only `startsWith('NQ')`. A correct IBAN mod-97 impl
   (`ibanCheck`) already exists in `src/lib/verify-signature.ts` but is used only to derive,
   never to validate payout addresses. ~1h fix, highest severity-per-line in the repo.
2. **C2 scan-to-pay silent failure** — `pay-request.ts` comment says nonce is "only a preferred
   tiebreaker… must not depend on it"; `api/tips/detect/route.ts` implements `if (nonce && !nonceMatch)
   return {found:false}` — a hard gate. If the wallet drops `message`, money moves, poll never
   matches, wall shows nothing, no error surfaced. Comment and code contradict each other.
3. **C3 200-tip cap** — `LPUSH` + `LTRIM 0 199` in `addTip`/`recordTipAtomically`. Lifetime totals
   survive via `vtotal` aggregates but messages are destroyed. Contradicts "leave a mark" promise;
   `DashboardExport` only exports the last 200 ("Your tips are yours" is false past 200).
4. **C4 reverify-on-read amplification** — `reverifyPendingTips` never resolves `unavailable`
   tips, so every wall/dashboard GET re-runs up to 6 attempts × 2 upstreams per pending tip, forever.

### Also flagged
- H1 GET endpoints write to KV (`reverifyPendingTips`, `getVerifiedTipCount` SADDs per call).
- H2 no confirmation-depth check; `addVerifiedNim` has no reversal path.
- M1 "pledge monthly" collects email, no scheduler exists — non-functional promise.
- M2 no moderation (creator can reply but not hide/delete a tip).
- M3 i18n 10 langs on supporter path only; dashboard/edit English.
- M6 zero API-route / integration tests; Playwright installed but no E2E in CI.
- Biggest product risk: supporter must acquire NIM; no balance check, no on-ramp. Competition
  **allows USDT** → USDT path is the highest-leverage funnel fix.
- Nimiq Hub desktop popup is the best non-crypto UX but is buried behind `nimiqAvailable === false`
  and jargon-labelled — should be the primary desktop CTA.

### Second-pass findings (appended to review as §8b)
- **X1 no security headers at all** — `next.config.ts` has no `headers()` block. No CSP,
  X-Frame-Options, HSTS, nosniff, Referrer-Policy. ~15 lines. App is embed-friendly
  (overlay + `/embed/[handle]`), so CSP must be written deliberately, not copy-pasted.
- **X2 rate limiting covers only 8 of 21 API routes.** Worst offenders unprotected:
  `/api/tips/[handle]` GET (calls `reverifyPendingTips` → makes C4 an on-demand
  amplification vector), `/api/stats/ecosystem` (heaviest read: every profile + every tip
  list + `getVerifiedTipCount`'s unbounded SADD loop), `/api/dashboard/[handle]` GET (also
  reverifies), `/api/profile/create` (unlimited walls + no address validation → inflates
  the very ecosystem stats being judged).
- **X3 `@nimiq/core` (27MB) imported nowhere** — dead dep; `serverExternalPackages` entry in
  next.config.ts is cargo-cult. Only `mini-app-sdk` (78K) + `hub-api` (160K, correctly
  dynamic-imported in hub.ts) are used.
- **X4 no observability** — console.error only, no Sentry, nothing polls `/api/health`.
  Matters because prize months 2–3 require "still live and continuously accessible".
- **X5 ShareKit `embedHtml` interpolates `displayName` into HTML unescaped** (low, self-inflicted).
- **Verified clean:** zero XSS sinks (all user content = JSX children, auto-escaped);
  `/api/og` correctly fetches only the profile's stored URL (not an open proxy);
  `/api/tips/[handle]/reply` fully owner-gated (signature + ownerPublicKey + nonce + rate limit);
  design system = 5 palettes via CSS custom properties, only 385 lines CSS total.
- Did NOT verify local `next build` (killed at 10min, slow on this box). CI gates it.

## NIM coin logo extraction (same day, after logo concepts)

User asked to extract the NIM coin logo "from the website". Key finding:

**There is no separate official "NIM coin" logo.** NIM is represented by the Nimiq gold
hexagon. Verified by exhaustive check:
- `nimiq.dev/design-kit` hosts only 8 brand assets (hexagon / horizontal, colored+mono+white).
- Probed `nimiq.dev/logos/` for `nim.svg`, `nimiq/nim.svg`, `cpl.svg`, `token.svg`,
  `crypto-payment-logo.svg` → all 404.
- `nimiq/designs` repo (GitHub API tree): only `logo/` + `nimiq-logo.min.svg`, zero NIM-specific paths.
- nimiq.com's own icon set (`i-nimiq:*`, 23 icons) contains `logos-nimiq` (gold hexagon) and
  `logos-cpl-tag` (Crypto Payment Logo — **blue** #265DD7→#0582CA, hexagon with hexagonal hole).
  The CPL is generic-crypto, NOT NIM-specific — don't mistake it for the NIM mark.
- `NimiqToolbox/nimiq-ui-kit` icon sprite has `nq-hexagon` but no NIM token icon.

### Official NIM mark specs
- Geometry: rounded hexagon, viewBox `0 0 20 18`, wider than tall, points left/right.
- Fill: radial gradient `matrix(-19.9562 0 0 -18 19.956 18)`, stops `#EC991C` → `#E9B213`.
- Note TipWall's own `--tw-gold #f6b221` is a *different* gold — if TipWall's coin sits next
  to the NIM mark they will visibly clash. Pick one or tint the NIM mark to match.

### Assets in `marketing/nim-assets/`
- `nim-hexagon-official.svg` — official mark, normalized (double quotes, stable gradient id).
  **Verified pixel-identical to `official-hexagon.svg`** (md5 match at 16/32/64/512 px).
- `nim-hexagon-mono.svg` — `currentColor` variant for ink/small-size use.
- `nim-coin-round.svg` — circular gold coin + NIM hexagon knocked out in cream. Reads as "money"
  most universally (community asked for money in the logo).
- `nim-coin-hexagon.svg` — official hexagon at 64px with ink outline + inset rim (coin edge).
- `nimiq-icons/` — all 23 official `i-nimiq:*` SVGs extracted from nimiq.com via
  `extract-icons.mjs` (parses data-URIs out of the page CSS).
- `render.mjs` → `renders/` (512/64/32/16 PNGs + `_sheet.png` contact sheet).

### Gotchas
- `/tmp` is NOT writable in this sandbox — `curl -o /tmp/x` fails with exit 23. Write into the
  workspace instead.
- Do not use `WebFetch` for raw SVG/asset files; it converts to markdown and mangles markup.
  Use `curl` for binary/source assets, `WebFetch` only for prose pages.
