### Gotchas

- **ffmpeg is NOT on PATH.** It comes from `ffmpeg-static`:
  `FF=$(node -p "require('ffmpeg-static')")` →
  `node_modules/ffmpeg-static/ffmpeg.exe`. Bare `ffmpeg` / `ffprobe` silently do
  nothing; `ffprobe` does not exist at all. Use `"$FF" -hide_banner -i file.mp4`
  to read specs.
- Don't pipe the ffmpeg path through `xargs -I{}` — the path has spaces on
  Windows and it fails with exit 1. Assign to a var and quote it.
- **API keys are already populated** in `scripts/promo/.env.local` (gitignored):
  `ELEVENLABS_API_KEY` (51 chars) and `RUNWAYML_API_SECRET` (132 chars) are set;
  `ELEVENLABS_VOICE_ID` is empty (defaults to Rachel,
  `21m00Tcm4TlvDq8ikWAM`). So the paid path is available, and the free path
  (`synth-voiceover.ps1`, Windows SAPI) is already written.

### Mistake to remember

First pass added burned-in drawtext captions. They created **double-text noise**
because the source video is already a heavy motion-graphics piece with its own
on-screen text on every scene (launch page hero, "So why is saying thanks so
broken?", "Meet TipWall" beats). Re-rendered WITHOUT captions. Lesson — before
adding captions, check whether the source already has on-screen text, and if it
does, captions are usually noise. Source voiceover carries the story; visual
text duplicates it.

### Reframe gotcha (verified)

Source aspect 700/1456 = 0.4808, target 1080/1920 = 0.5625. Source is TALLER
than target (height-limited fit). `scale=-2:1920` on the fg keeps the full
content at 923×1920; blurred bars on each side (78px each at the rendered
output). Use blurred-fill bg, NOT crop, for screen recordings — cropping cuts
content.
